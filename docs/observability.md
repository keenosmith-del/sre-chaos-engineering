# Real telemetry

Every Go process initializes the OpenTelemetry trace SDK and sends OTLP HTTP spans to the Collector. The Collector batches to Jaeger. Gateway HTTP -> ordering saga -> inventory and payment HTTP spans -> persisted RabbitMQ trace headers -> worker consume span form a distributed trace. JSON logs include trace/correlation IDs. Jaeger uses local in-memory storage, so traces are lost on its restart.

Prometheus scrapes native Go metrics every three seconds and RabbitMQ per-object metrics. Grafana provisions Prometheus/Jaeger data sources and a reliability dashboard. Traces use OpenTelemetry; metrics use the mature Prometheus client rather than an OpenTelemetry metric exporter. Operational metrics include HTTP status/duration, durable outcomes, dependency retries/circuits, outbox age/backlog, reconciliation, worker outcomes and broker queue/redelivery metrics. Overview uses actual service HTTP readiness and control metrics.

Experiment snapshots query each baseline/failure/recovery window and persist exact PromQL with numeric availability metadata. Throughput is gateway POST /api/orders requests per second. Infrastructure error fraction counts gateway order-submit HTTP 5xx divided by all order submissions. Payment declines are expected successful business responses and excluded from infrastructure errors. Completion rate counts durable CONFIRMED transitions per second; it is distinct from API acceptance throughput. p50/p95/p99 are histogram estimates from gateway order-submit durations. Queue/outstanding/outbox values are point-in-time gauges at the end of a window; retry/circuit values use increases in that window. Prometheus increase extrapolates at window boundaries, so estimates may be fractional with short windows.

Insufficient/no samples or undefined denominators return available:false and a reason. An absent time series is not a fabricated zero. Durable backlog gauges refresh independently every two seconds and through ordering /stats. SQL failures set them to NaN (unavailable) rather than retaining a healthy-looking old value. Broker statistics collect every second; Prometheus scrapes every three seconds, so gauges are recent scrape samples rather than an atomic distributed snapshot. Missing queue metric series before the first queue exists may be unavailable. RabbitMQ queue metrics are obtained directly from its real exporter; no queue-depth simulation runs in the UI.

Open Grafana http://localhost:3000/d/reliability and Jaeger http://localhost:16686. Transaction inspector links a real trace ID. Sampling exports all local spans; use production sampling/retention policies before scaling. Service-specific logs can be read with `docker compose logs ordering inventory payments worker`.
